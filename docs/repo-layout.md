# Expected GitHub Repo Layout

Each client site generated by AFO Micro SEO Site Builder MCP is stored in its own GitHub repository. This document defines the expected layout.

---

## Standard Layout

```
{client-site-repo}/
├── afo.site.bundle.json          # The AFO Site Bundle Manifest (source of truth)
├── worker/
│   ├── wrangler.toml             # Cloudflare Worker config
│   ├── package.json
│   ├── src/
│   │   └── index.ts              # Worker entry point
│   └── public/
│       ├── llms.txt
│       ├── robots.txt
│       └── sitemap.xml
└── receipts/
    └── {bundle_id}-{timestamp}.json   # Deployment receipts (written by Mobile Terminal)
```

---

## Rules

- `afo.site.bundle.json` must be at the **repo root**
- Worker files must be in the `worker/` directory
- `worker_path` in the bundle's `repo` section must match the actual path
- Receipts are written to `receipts/` — this directory must exist (use `.gitkeep` to initialize)
- Do not commit secrets, API keys, or Cloudflare tokens to the repo

---

## `repo` Section in Bundle

The bundle's `repo` section points back to itself:

```json
"repo": {
  "owner": "nothinginfinity",
  "name": "capistrano-plumbing-site",
  "branch": "main",
  "worker_path": "worker",
  "bundle_path": "afo.site.bundle.json"
}
```

AFO Mobile Terminal uses these values to locate and read all files.

---

## GitHub as Source of Truth

Cloudflare Workers is **only** the runtime. The canonical definition of the site — its config, content, and deployment history — lives in GitHub.

- To update the site: update GitHub → redeploy via Mobile Terminal
- To audit what was deployed: read the bundle and receipt from GitHub
- Never edit Worker config directly in the Cloudflare dashboard without updating GitHub
